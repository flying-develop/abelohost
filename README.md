# Блог на PHP, MySQL и Smarty

Тестовое задание: простой, полностью рабочий блог на чистом PHP без фреймворков.

## Техническое задание

### Стек

- PHP 8.1 или новее; для проекта выбрана версия 8.4.
- MySQL и шаблонизатор Smarty.
- Использование фреймворков запрещено.
- SCSS и Docker-окружение будут плюсом.

### Данные

| Сущность | Поля |
| --- | --- |
| Категория | Название, описание |
| Статья | Изображение, название, описание, текст, одна или несколько категорий, количество просмотров |

Для вывода последних статей и сортировки также потребуется дата публикации.

### Обязательные страницы

- **Главная:** вывести каждую категорию, в которой есть статьи, и три последних поста по дате публикации. Для каждой категории добавить кнопку «Все статьи».
- **Категория:** название, описание, список статей, сортировка по количеству просмотров и дате публикации, пагинация.
- **Статья:** вся информация о статье и блок из трёх похожих статей.

Дополнительно необходимо реализовать сидинг категорий и статей.

### Критерии оценки и сдача

Оцениваются простота, читаемость и структура кода, структура проекта, работа с MySQL, уровень самостоятельной реализации и глубина понимания решения.

Результат сдаётся ссылкой на открытый репозиторий GitHub, GitLab или Bitbucket. Нужно указать, использовался ли ИИ, и для каких конкретно задач. Желательны поэтапные коммиты, отражающие ход разработки.

## Этапы разработки

1. **Окружение и каркас:** PHP-FPM, nginx, MySQL, Composer/Smarty, Vite/SCSS/Bootstrap, проверочная страница.
2. **Данные:** таблицы, связи категорий и статей, подключение через PDO, сидинг.
3. **Блог:** обязательные страницы, сортировка, пагинация, просмотры и похожие статьи.
4. **Подготовка к сдаче:** проверки, оформление, документация и публикация репозитория.

Сейчас подготовлены файлы первого этапа. Логика блога, таблицы и сидер ещё не реализованы. Зависимости и контейнеры требуют проверки в окружении с доступом к Docker и сети.

## Структура

```text
public/index.php       Точка входа PHP
public/build/          Результат сборки Vite, не хранится в Git
src/js/                JavaScript
src/scss/              SCSS и подключение Bootstrap
src/images/            Исходные изображения
templates/             Шаблоны Smarty
var/smarty/            Компиляция шаблонов и кеш, не доступны через HTTP
docker/php/            Образ PHP и настройки php.ini
docker/nginx/          Конфигурация веб-сервера
docker-compose.yml     Сервисы окружения
composer.json          PHP-зависимости
package.json           JS-зависимости и команды сборки
```

Данные MySQL расположены вне проекта: по умолчанию `../abelo-storage/mysql`.

## Локальный запуск

Требуются Docker Engine / Docker Desktop и Docker Compose v2. PHP, Composer и Node на хосте устанавливать не нужно.

### 1. Конфигурация

```bash
cp .env.example .env
mkdir -p ../abelo-storage/mysql
```

Установите в `.env` пароли базы данных. Для Linux задайте `LOCAL_UID` и `LOCAL_GID` по результатам `id -u` и `id -g`, чтобы создаваемые контейнерами файлы принадлежали вашему пользователю. По умолчанию оба значения равны `1000`.

Если меняете `MYSQL_STORAGE_PATH`, заранее создайте соответствующий каталог. Compose не создаёт его автоматически. Для MySQL используйте новый пустой каталог; при последующих запусках сохраняйте существующие данные.

Для каталога MySQL явно установлен режим `rprivate`: приложению не требуется передача вложенных монтирований между хостом и контейнером. Подробнее — в [документации Docker о bind mounts](https://docs.docker.com/engine/storage/bind-mounts/#configure-bind-propagation).

### 2. PHP-зависимости

```bash
docker compose build php-fpm
docker compose run --rm --no-deps php-fpm composer install
```

### 3. Ресурсы

При первом запуске до появления `package-lock.json`:

```bash
docker compose run --rm --no-deps node npm install
docker compose run --rm --no-deps node npm run build
```

Сохраните созданный `package-lock.json` в Git. При наличии lock-файла устанавливайте зависимости через `npm ci` вместо `npm install`.

Vite собирает `src/js/app.js` вместе с SCSS и используемыми изображениями в `public/build`. Перед сборкой выходной каталог очищается. Итоговые CSS/JS имеют имена `app.css` и `app.js`, изображения — имена с хешем. Пользовательские файлы храните в `src`, поскольку содержимое `public/build` перезаписывается.

### 4. Сайт

```bash
docker compose up -d
```

Откройте **http://localhost:8080**. Кнопка «Проверить Bootstrap» раскрывает блок и позволяет проверить подключение JavaScript.

Порт меняется через `HTTP_PORT`. Сайт доступен только на localhost. MySQL доступен внутри Compose по имени `mysql`, без публикации порта на хост. PHP начинает работу после успешного healthcheck базы.

Если зависимости или сборка отсутствуют, точка входа отвечает HTTP 503 с подсказкой. Ошибки PHP записываются в журналы контейнера.

## Разработка и управление

Пересборка ресурсов при изменениях, в отдельном терминале:

```bash
docker compose run --rm --no-deps node npm run watch
```

После изменения ресурсов обновляйте страницу вручную. HMR-сервер не используется.

```bash
docker compose ps
docker compose logs -f nginx php-fpm mysql
docker compose down
```

`down` удаляет контейнеры и сеть, но сохраняет данные MySQL в соседнем каталоге. После первой инициализации изменение паролей в `.env` не меняет учётные записи в существующей базе автоматически.

### Ошибка `not a shared mount`

Это ошибка подключения каталога на стороне Docker, возникающая до запуска MySQL. В Compose проекта используется `rprivate`, а не `shared` или `rshared`. Если ошибка появилась, выполните из терминала хоста в каталоге проекта:

```bash
mkdir -p ../abelo-storage/mysql
docker compose config --quiet
docker compose up -d --force-recreate mysql
```

Если в `.env` задан другой `MYSQL_STORAGE_PATH`, создайте именно этот каталог. При успешном запуске MySQL запустите остальные сервисы командой `docker compose up -d`.

Если ошибка сохраняется, проверьте итоговую конфигурацию: дополнительные Compose-файлы могут переопределять тома. В Docker Desktop с WSL проверьте включённую интеграцию для дистрибутива, доступность каталога из этого дистрибутива и перезапустите Docker Desktop. Повторите запуск MySQL. Не удаляйте каталог с существующими данными.

Если контейнер уже создан, параметры переданного Docker монтирования можно получить без вывода паролей:

```bash
docker inspect abelo-mysql-1 --format '{{json .HostConfig.Mounts}}'
```

Имя контейнера соответствует `COMPOSE_PROJECT_NAME=abelo`; при другом имени проекта используйте имя его контейнера MySQL. Перезапуск Docker Desktop и фактическое монтирование из текущей сессии не проверены.

## Проверки первого этапа

```bash
docker compose config --quiet
docker compose run --rm --no-deps php-fpm composer validate --strict
docker compose run --rm --no-deps php-fpm composer check-platform-reqs
docker compose run --rm --no-deps php-fpm php -l public/index.php
docker compose run --rm --no-deps node npm run build
docker compose exec nginx nginx -t
curl -f http://localhost:8080/
```

Проверка подключения PDO под пользователем приложения:

```bash
docker compose exec -T php-fpm php -r '
$pdo = new PDO(
	"mysql:host=" . getenv("DB_HOST") . ";port=" . getenv("DB_PORT") . ";dbname=" . getenv("DB_DATABASE") . ";charset=utf8mb4",
	getenv("DB_USERNAME"),
	getenv("DB_PASSWORD")
);
echo $pdo->query("SELECT 1")->fetchColumn(), PHP_EOL;
'
```

Ожидаемый результат — `1`. Также проверьте загрузку `/build/app.css` и `/build/app.js`, работу кнопки, пересборку при изменении SCSS и удаление устаревших файлов при повторном build.

Запросы к `/.env`, `/vendor/autoload.php` и `/templates/home.tpl` не должны раскрывать содержимое файлов. Для проверки сохранения БД создайте контрольную запись в отдельной временной таблице, пересоздайте контейнеры и убедитесь, что запись сохранилась; затем удалите временную таблицу.

В текущей сессии прошли проверка конфигурации Compose, валидация Composer и проверка синтаксиса PHP/JS. Composer lock-файл сформирован из локального кеша метаданных. Установка пакетов, сборка Vite, HTTP-проверки, PDO и сохранение данных пока не проверены: Docker daemon недоступен, DNS для Packagist/npm не работает. `package-lock.json` ещё не сформирован. Тестовый фреймворк на первом этапе не подключён.
